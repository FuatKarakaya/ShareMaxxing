# Cloud setup and automatic deployment — WBS-29.1, WBS-29.2

The live site runs on two free services:

| Part | Where | Notes |
|---|---|---|
| API (`backend/`) | Render web service `sharemaxxing-api` | Node 22, Frankfurt |
| Website (`frontend/`) | Render static site `sharemaxxing-web` | Built with Vite |
| Database | Neon PostgreSQL | Frankfurt, one database |

Render reads its settings from [`render.yaml`](../render.yaml) in the repository
root. Change the file through a pull request, not in the Render Dashboard.

## Automatic deployment

Every merge to `main` goes live on its own:

1. GitHub Actions runs the CI checks on `main`.
2. When the checks pass, Render builds and deploys the API and the website.
   If a check fails, nothing is deployed.
3. The API build runs `npm run build`, which also applies new Prisma migrations
   to the live database.

The website is rebuilt only when `frontend/` or `render.yaml` changes, and the
API only when `backend/` changes.

## Settings

| Variable | Service | Value |
|---|---|---|
| `DATABASE_URL` | API | Neon connection string. Entered in the Render Dashboard only |
| `JWT_SECRET` | API | Generated by Render |
| `FRONTEND_ORIGIN` | API | Address of the website. The API accepts browser calls from this address only |
| `TRUST_PROXY_HOPS` | API | `1`, so the login rate limit sees the visitor's address instead of Render's proxy |
| `VITE_API_BASE_URL` | Website | Address of the API followed by `/api` |
| `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL` | API | AI provider, see [AiProvider.md](AiProvider.md). Added by hand under **Environment** in the Render Dashboard, not through `render.yaml` |

No secret is stored in the repository. `VITE_*` values are visible in the
browser, so they must never hold a secret.

## One-time setup

1. The repository owner installs the Render GitHub app for this repository:
   <https://github.com/apps/render/installations/new>.
2. Create a Neon project in the Frankfurt region and copy the direct
   connection string (connection pooling switched off).
3. In Render choose **New > Blueprint**, pick this repository and the `main`
   branch, and paste the Neon connection string when Render asks for
   `DATABASE_URL`.
4. Check the two addresses Render gives. If they are not
   `sharemaxxing-api.onrender.com` and `sharemaxxing-web.onrender.com`,
   update `FRONTEND_ORIGIN` and `VITE_API_BASE_URL` in `render.yaml`.
5. Open `https://sharemaxxing-api.onrender.com/health`. It should answer
   `{"status":"ok"}`. Then open the website and log in.

Sample users are not created automatically. Demo data is loaded separately
(WBS-32.2).

## Limits of the free plan

- The API sleeps after 15 minutes without requests. The next request wakes it
  up, which takes about one minute. Open the site a few minutes before a demo
  or a test.
- The free API cannot send email through SMTP ports 25, 465 and 587. The
  verification email (WBS-1.2) needs a mail provider that offers another port,
  such as 2525, or an HTTP API.
- The live database is shared. Do not run `db:reset` or the mock seed against it.
